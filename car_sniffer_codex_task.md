# Car Sniffer — задание для Codex

Создать прошивку STM32F407VET6 и приложение Windows для диагностики автомобильных CAN-сетей и синхронного наблюдения за восемью аналоговыми напряжениями. Реализовать рабочий MVP по требованиям ниже, включая документацию, сборку и проверку. Сначала прочитать AGENTS.md, существующий код и описание установленного toolchain, если они есть. Не предполагать наличие подключённого оборудования. Отдельно указывать, что проверено на устройстве, что симуляцией, а что только сборкой.

## 1. Оборудование и стек

- Отладочная плата STM32F407VET6, корпус LQFP100, 512 КБ Flash. Не использовать linker script варианта с 1 МБ Flash.
- Два TJA1050, питание 5 В; их RXD выдаёт логический уровень около 5 В.
- Восемь внешних управляемых делителей с номинальными коэффициентами 1:1 и 1:5. Схема нелинейна; измерения требуют калибровки.
- Прошивка: C, STM32Cube HAL/LL, CMake + Ninja, arm-none-eabi toolchain, OpenOCD для SWD. Использовать существующий toolchain проекта.
- USB OTG FS device, класс CDC ACM; двоичный протокол поверх виртуального COM-порта.
- Windows GUI: Python, PySide6, pyqtgraph, pyserial. Версии зависимостей фиксировать. Дать команду запуска и сборку приложения через PyInstaller.
- MVP использует встроенные bxCAN. CAN FD, побитовое декодирование повреждённых кадров, BEAN и произвольная генерация CAN-пакетов не входят в задачу.

## 2. Назначение пинов и аппаратные ограничения

Codex должен предложить таблицу пинов: функция, GPIO, AF/ADC channel, электрические ограничения, соединение с внешней схемой. Все назначения вынести в board configuration, чтобы их можно было заменить без изменения логики.

- Для обоих CAN_RX выбрать FT (5 V tolerant) GPIO, проверенные по datasheet именно STM32F407VET6 в режиме используемой alternate function. Проверить ограничения FT, pull-up/pull-down и последовательности питания. Не считать ADC-пины устойчивыми к 5 В.
- Проверить совместимость CAN_TX 3,3 В с порогами TXD TJA1050 по datasheet.
- Для каждого делителя выделить отдельный GPIO, который умеет только тянуть к GND либо переходить в Hi-Z. Реализация: open-drain, запись 0 = GND, запись 1 = отпустить линию; внутренние подтяжки отключены. Никакого активного HIGH. Проверить FT, если внешняя схема поднимает управляющую линию выше 3,3 В.
- Соответствие GND/Hi-Z диапазонам пока неизвестно. Вынести его в конфигурацию, явно отметить необходимость сверки со схемой. Нельзя объявлять безопасный диапазон установленным до этой сверки. После сверки при старте выбирать диапазон 0–15 В без кратковременного перехода в 1:1.
- Предложить 8 ADC-входов, оба CAN RX/TX, USB, 8 управляющих GPIO; сохранить SWD. Учесть занятость пинов обвязкой конкретной платы. Если схемы платы нет, предложить назначение с перечнем необходимых проверок, не выдавать его за подтверждённое.
- Проверить HSE конкретной платы и согласовать clock tree CAN/ADC/USB; USB требует точных 48 МГц. Частоту кварца не угадывать.
- Документировать терминаторы каждого нового CAN-сегмента и возможные встроенные 120 Ом на модулях TJA1050. Прошивка не обеспечивает электрическую изоляцию питания/земель и не заменяет правильную терминацию.

## 3. CAN: независимые состояния моста и захвата

У устройства две стороны: A (CAN1), B (CAN2). Названия использовать одинаково в GUI, протоколе и документации.

### Мост включён

- Каждый корректно принятый кадр A передавать в B, каждый кадр B — в A. Сохранять ID, IDE, RTR, исходный DLC и DATA; у RTR данные отсутствуют. Поддержать стандартные и расширенные ID, Classic CAN.
- Это мост с приёмом полного кадра и последующей передачей. Контроллер локально подтверждает кадр ACK; подтверждение исходному отправителю не означает успешную доставку на другую сторону. Ошибочные кадры и error frames не пересылаются.
- Логировать один RX с исходной стороны и связанные события TX на противоположной; успешную пересылку не отображать как новый внешний RX. Не удалять одинаковые реальные кадры по совпадению ID/DATA: они могут законно приходить с обеих сторон.
- Работа моста полностью на MCU, без участия Windows и USB. Остановка захвата, фильтрация, сброс GUI и отключение USB не останавливают мост. После сброса питания мост выключен до явного включения.
- Мост разрешать только при подтверждённых одинаковых скоростях сторон. При изменении скорости работающего моста сначала остановить пересылку с явным сообщением.
- RX ISR короткие; ограниченные очереди отдельно по направлениям, неблокирующая передача. Документировать порядок очереди и влияние арбитража. Учесть общие filter banks CAN1/CAN2 и необходимость clock CAN1 для CAN2.
- Сбой B не должен блокировать приём, диагностику и USB на A. Ввести конечный срок доставки и ограничение повторов/очереди; не повторять бесконечно недоставляемый кадр. При ACK error, bus-off или переполнении явно регистрировать событие и исходный кадр, если он известен. После восстановления не выпускать накопленный устаревший поток.
- Для bus-off описать и реализовать контролируемое восстановление с ограничением частоты попыток. Сторона, время, причина и потери видны пользователю. Политика восстановления не должна создавать бесконечный цикл перезапуска.

### Мост выключен

- Две независимые шины, без пересылки, по умолчанию оба контроллера в silent/listen-only: без ACK и активных error flags.
- Скорости A и B можно выбирать независимо.
- Отключение моста не соединяет провода физически. Если прибор стоит в разрыве, сегменты остаются разделены. Для пассивного наблюдения общей шины подключить один конец без разрыва.

### Скорость

- Для каждой стороны доступны Auto и ручной выбор: 125, 250, 500, 1000 кбит/с; добавить 100 и 83,333 кбит/с, если clock tree позволяет получить приемлемую точность. Таблицу bit timing и sample point документировать.
- Auto перебирает поддерживаемые скорости только в silent mode, с ограниченным временем попытки и подтверждением несколькими корректными кадрами. Возвращает найденную скорость или «не определена», не угадывает при отсутствии трафика.
- На изолированной стороне с единственным отправителем отсутствие ACK может мешать успешному приёму и Auto. Предусмотреть понятный статус и ручной выбор. Не переходить в активную передачу для определения скорости.
- Не запускать поиск скорости незаметно на работающем мосту.

## 4. Что показывать по CAN

Строка кадра: время MCU, сторона исходного RX, ID hex, IDE 0/1, RTR 0/1, DLC decimal, DATA hex. В интерфейсе сторона определяется также заголовком таблицы.

Требование CRC_OK/ACK реализовать без вымышленных измерений:

- CRC_OK = 1 для успешно принятого кадра означает аппаратную проверку bxCAN. Некорректный CRC регистрировать отдельным событием; bxCAN не предоставляет полноценную строку повреждённого кадра с ID/DATA и CRC_OK=0.
- ACK_RX = N/A: ACK bit каждого принятого внешнего кадра недоступен через receive mailbox. Не выводить фиктивную единицу.
- TX_ACK: pending / 1 / 0 / N/A. 1 — собственная пересылка успешно завершена в normal mode; 0 — зарегистрирован ACK error данной TX-попытки, если удалось достоверно связать его с кадром. Иначе событие ACK error относится к контроллеру без ложной привязки. При отключённом мосте — N/A.
- Статус пересылки отдельно: pending, sent, failed, expired, dropped; потеря арбитража сама по себе не означает неисправность шины.

Отдельные события/статусы для A/B:

- Доступные LEC: stuff, form, ACK, bit recessive/dominant, CRC error.
- TEC/REC, error warning, error passive, bus-off и восстановление.
- RX FIFO overflow, TX queue overflow, истечение срока пересылки, потери диагностических данных из-за USB/буферов.
- Счётчики RX/TX, ошибок и потерь отдельно для сторон; единая временная шкала с аналоговыми входами.

LEC — последнее наблюдаемое состояние, а не гарантированная запись каждого физического error frame. Описать пределы полноты регистрации, связь событий с кадрами и невозможность однозначно установить виновный ECU только по error counters. CRC протокола USB не путать с CRC CAN.

## 5. Аналоговые измерения

- 8 каналов, диапазоны интерфейса 0–3,3 В и 0–15,0 В, независимо переключаемые вручную.
- Номинальная математика делителя 1:5 даёт 16,5 В при ADC full scale 3,3 В. Не подменять коэффициент 5 коэффициентом 15/3,3 ради подписи диапазона. После калибровки использовать фактическую характеристику.
- Итоговая частота ровно 100 Гц на каждый канал. Начальный oversampling: 16 отсчётов на канал за 10 мс, равномерно распределённых, арифметическое среднее. Это 1600 scan/s × 8 = 12 800 преобразований/с. Достаточно одного ADC с последовательным scan, таймером и DMA; ADC не выполняет каналы одновременно.
- Настроить sample time под реальное выходное сопротивление делителя и требования settling ADC. До получения схемы сделать его конфигурируемым и указать условие аппаратной проверки. Разрядность исходного ADC 12 бит; усреднение не гарантирует дополнительных эффективных битов.
- DMA-буферы поместить в доступную DMA SRAM, не CCM. Запись, усреднение и USB не блокируют обработку CAN.
- У каждой точки timestamp окна, channel, range, raw average, calibrated voltage, calibration version и quality flags. Для нелинейной характеристики преобразовывать каждый сырой отсчёт перед усреднением; raw average хранить отдельно для диагностики.
- Контролировать clipping по сырым отсчётам, даже если среднее находится ниже предела. Отображать выход за заданный диапазон и недействительность измерения, не прижимать напряжение молча к границе.
- После переключения диапазона дождаться configurable settling interval и отбросить переходные измерения. Точки пометить событием переключения; не проводить непрерывную линию через недействительный участок.
- Захват отдельного канала можно отключить без влияния на остальные. ADC scan допустимо оставить постоянным для предсказуемого timing.

## 6. Калибровка нелинейных делителей

Отдельная характеристика для каждого из 8 каналов и каждого из 2 диапазонов: всего 16 профилей. Основной метод — таблица «raw ADC → истинное напряжение», монотонная кусочно-линейная интерполяция, без полинома высокого порядка.

### Постоянное напряжение и внешний вольтметр

- В диалоге выбрать канал и диапазон, подать постоянное напряжение, ввести показание внешнего вольтметра, накопить raw данные и добавить точку.
- Показывать raw mean, разброс и clipping; не принимать нестабильную или насыщенную точку.
- Поддержать минимум 2 точки и рекомендовать несколько по диапазону, включая нулевую и близкую к верхнему пределу без насыщения.
- Проверять монотонность и близкие/дублирующиеся raw значения. Показывать таблицу, график характеристики и границы калиброванного участка. Вне участка помечать значение как некалиброванное; не экстраполировать молча.

### Синус известной амплитуды

- Пользователь задаёт частоту, амплитуду и её определение (peak / peak-to-peak / RMS), а также DC offset. Для униполярного входа весь сигнал обязан оставаться внутри допустимого диапазона: отрицательная полуволна без смещения недопустима.
- Собирать сырой поток до 100-Гц усреднения, на MCU timer + DMA; начально 1600 отсчётов/с на канал. Ограничить частоту калибровочного синуса, например ≤20 Гц, собирать несколько полных периодов и проверять достаточность выборки.
- Одна известная амплитуда без известного offset и дополнительных опорных точек не определяет произвольную нелинейность. Не выдавать простой RMS-коэффициент за полноценную нелинейную калибровку.
- Предложить и реализовать определение нелинейной таблицы по фазово привязанному опорному синусу с заданным offset, учётом неизвестной фазы и отдельной проверки восходящей/нисходящей ветвей. Reject при clipping, нестабильности, недостаточном покрытии, немонотонности или существенном расхождении ветвей. Проверить алгоритм на синтетической известной нелинейной функции, а также задержке, шуме и clipping.
- Если достоверная идентификация нелинейности невозможна, явно ограничить результат коррекцией масштаба существующей DC-калибровки. Не записывать недостоверную таблицу. Документировать пределы метода.
- Raw calibration stream ограничить по скорости и длительности, чтобы он не мешал CAN-мосту. События CAN и счётчики продолжают работать; возможные изменения обычного ADC-захвата отражать явно.

Сохранять калибровочные профили и настройки в приложении (JSON, версия схемы, идентификатор устройства). Это не сохранение сеансов захвата. При подключении загружать профили в MCU для пересчёта отдельных отсчётов; без компьютера использовать номинальную характеристику и флаг uncalibrated. Постоянное хранение профилей в Flash MCU не требуется в MVP. Профили привязывать к устройству и проверять при смене платы; не применять чужую калибровку автоматически.

## 7. USB и временная шкала

- Версионированный двоичный framing: тип, длина, sequence number, payload, checksum/CRC транспорта; parser восстанавливается после повреждения и фрагментации. Явно зафиксировать endian, типы и ограничения длины.
- Команды с request ID и ответами: состояние устройства, CAN mode/bitrate/Auto, enable/disable bridge, start/stop capture, channel enable/range, калибровочные профили/raw session, очистка результатов/счётчиков в согласованных границах.
- Данные: CAN RX, TX status, ошибки/состояния, ADC batches, Auto progress/result, statistics. Формат описать и реализовать одинаково в C и Python.
- Все события датируются MCU общим монотонным счётчиком в микросекундах, расширенным для работы без неоднозначности при wrap. Указывать точку timestamp CAN RX: момент обработки приёма, а не аппаратно измеренный SOF. Сброс MCU обозначать новой сессией/boot ID.
- Бинарные пакеты и batching; никакого JSON или printf на каждый CAN frame. Оценить USB throughput для двух сильно загруженных шин, включая короткие кадры.
- Forwarding queues и telemetry queues разделены. Переполнение USB телеметрии никогда не останавливает мост. Все потери считать и показывать; медленный GUI не должен приводить к скрытой потере данных.
- При остановке захвата прекратить сбор новых результатов сеанса, но оставить управление, диагностику текущего состояния и мост работающими. Зафиксировать границу stop в timestamp и обработать оставшиеся пакеты предсказуемо.

## 8. Windows GUI

Строгий промышленный дизайн: плотная компоновка, нейтральные цвета, чёткие подписи, моноширинные CAN данные, минимум декоративных элементов. Один основной экран с двумя областями, разделёнными splitter.

Слева — 8 графиков друг под другом, общая ось времени. У каждого: channel name, capture enable, выбор диапазона, текущее напряжение, флаги clipping/calibration. Ось Y соответствует диапазону, переключение видно. Диалог калибровки открывается из этой области.

Справа — две таблицы рядом, A и B. Каждая показывает входящие с её стороны кадры и события ошибок; имеется независимая автопрокрутка и фильтр ID (hex, список/диапазон), IDE, RTR, кадры/ошибки. Фильтр влияет только на отображение, никогда на пересылку и сбор. TX status связан с исходной строкой. Пользователь может остановить автопрокрутку и изучить уже принятые результаты.

В общей панели: USB device/connect, скорости A/B и Auto, отдельный переключатель моста, Start/Stop capture, Clear results. Статус: USB, bridge state, CAN states/TEC/REC, счётчики потерь. Clear очищает результаты GUI без остановки моста и без сброса MCU; при активном захвате новые данные продолжают появляться.

Остановка захвата оставляет результаты для просмотра. Сохранение/открытие/экспорт записей не реализовывать. Буферы GUI ограничены; указать лимиты и явно обозначать удаление старых результатов. Графики можно прореживать только для отрисовки, не выдавать redraw frequency за sample rate.

USB I/O, parser и обработка данных вне GUI thread. Qt model/view для таблиц, пакетные обновления около 20–30 Гц; не создавать отдельный виджет на каждый кадр. Проверить отзывчивость при интенсивном потоке.

## 9. Результат и проверки

Результат: firmware/, desktop/, docs/ с исходниками, конфигурацией, инструкциями сборки/прошивки, pinout, protocol, calibration и описанием ограничений. Дать симулятор USB-устройства или demo backend для GUI без платы.

Обязательные проверки:

1. Прошивка собирается для F407VE; desktop запускается, зависимости воспроизводимы.
2. Parser C/Python: фрагментированные/склеенные пакеты, некорректная длина, CRC транспорта, sequence gaps, повторное подключение и reset MCU.
3. Мост: оба направления, стандартные/расширенные/RTR кадры, одинаковые реальные кадры с двух сторон, арбитраж, отсутствие ACK, bus-off, переполнение, отказ одной стороны. USB disconnect и capture stop не прекращают forwarding. Не заявлять аппаратные результаты без стенда.
4. Auto: правильная скорость, тишина, неподдерживаемая скорость и отсутствие ACK; никаких активных пробных передач.
5. ADC: 100 Гц на каждый канал, 16 отсчётов, timing/DMA, clipping, range settling, нелинейный пересчёт до усреднения, согласованные timestamps.
6. Калибровка: известная нелинейная характеристика, шум, offset/phase, clipping и выход за калиброванный участок; сохранение/загрузка профилей правильного устройства.
7. GUI под нагрузкой: обе CAN таблицы и восемь графиков, фильтры и независимая автопрокрутка, stop/clear, видимые счётчики потерь.

Начать с анализа доступных файлов и предложенного pinout/clock tree. Не блокировать разработку из-за отсутствующей схемы делителя: электрическое соответствие управляющих состояний и время settling оставить явными параметрами, реализовать остальной код и симуляцию. Перед испытанием на оборудовании сверить эти параметры, питание, пины и терминацию. Не подменять неподтверждённые аппаратные предположения молчаливыми значениями.
